# 7 篇 Paper 审稿视角缺口分析（2025‑12‑02）

> 目的：从“审稿人视角”总结每篇 Paper 当前已有的支撑与主要缺口，为后续完善实验与写作提供清晰清单。  
> 数据与状态参考：统一基线 v1/v3、12‑01/12‑02 的 GLM 报告与结果表。

---

## 1. 📘 1D‑2D Fusion Explainable

**当前支撑：**
- THU_018_basic 统一基线上表现极优：best run ≈ 99.57%，5 次迭代平均 ≈ 97%+；  
- 已有：性能对比图、模态贡献热图、注意力权重图、贡献度数据与分析报告；  
- 与 TSPN、ResNet 等 baseline 在单一数据集上的初步对比。  

**审稿视角下的缺口：**
1. **多数据集与多种子验证不足**  
   - 仅在 THU_018_basic 上给出结果，缺乏 CWRU/XJTU 等数据集的验证；  
   - 多 seed 统计虽有，但尚未在表格/正文中系统呈现。  
2. **系统的消融实验不完整**  
   - 需要：  
     - 三层对齐的消融（物理/语义/几何各缺一，对性能的影响）；  
     - 1D-only / 2D-only / 仅统计特征 vs 完整融合模型。  
3. **鲁棒性分析缺位**  
   - 噪声水平、工况（负载/转速）变化下的性能曲线；  
   - 至少一组错误案例分析（边界样本上模型输出 + 解释 + 人类判断）。  
4. **写作层面**  
   - Related work 对多模态 FD、1D+2D 融合的系统综述可以更全面；  
   - 需在正文中谨慎表述 99.57%，强调实验条件与局限，避免给人“过拟合”之感。

## 2. 🟠 MoE Explainable（物理约束专家系统）

**当前支撑：**
- THU_018_basic 上 MoE_simple ≈ 63.04% 准确率，训练稳定；  
- 专家激活热图、激活分布图、路径签名可视化、路由熵分析、专家决策混淆矩阵等可解释性结果齐全；  
- 已可展示“物理约束专家系统”的概念验证。  

**审稿视角下的缺口：**
1. **性能定位需更清晰**  
   - 对比对象不够系统：需要与  
     - 同参数量的单模型（更宽的 TSPN/ResNet）；  
     - 取消物理约束的 MoE；  
     - 简单集成方法（如 Bagging/Ensemble）  
     做性能与复杂度对比。  
2. **稳定性与泛化验证不足**  
   - 至少 2–3 个不同种子的结果；  
   - 至少 1 个额外数据集上的简化实验（哪怕只跑部分 epoch）。  
3. **理论主张与实证的映射还不够紧**  
   - “低频专家/谐波专家/包络专家”等命名，应在实验中用定量指标证明其激活模式与物理预期匹配；  
   - 路由熵、专家多样性与性能的关系可以用图表说明。  
4. **写作层面**  
   - 需要明确文章定位：偏 “可解释专家系统 baseline” 而非追求最高性能；  
   - 在讨论里主动承认当前性能差距，强调 MoE 的主要贡献在结构与解释性。

## 3. 🔴 TII Operator Attention（算子注意力）

**当前支撑：**
- 算子级注意力模块已在统一框架中实现并生成多种可解释性图表：算子权重热图、权重演化、注意力结构示意、L1 效果等；  
- 统一基线下性能 ≈ 20%（THU_018_basic），训练稳定但性能偏低；  
- L1 正则化调优实验已进行（部分结果进入 v3 表）。  

**审稿视角下的缺口：**
1. **性能尚未达到“可对话”的水平**  
   - 20% 准确率在 5 类故障诊断任务中过低，需要至少一个改进版本（比如靠近 TSPN 或中等水平）。  
2. **缺少与 Self-Attention / 常规注意力的系统对比**  
   - 至少需要 TSPN / Self-Attention-TSPN / OperatorAttention-TSPN 三者在性能 + 复杂度 + 可解释性上的对比。  
3. **理论论点的简洁验证**  
   - 针对算子级注意力的理论主张，需要用简单、可控的实验（如合成信号）证明：  
     - 算子权重确实与特定频段/算子性质对应；  
     - 与常规注意力相比，解释性或稳健性存在有意义差异。  
4. **写作层面**  
   - 更明确的定位为“理论/机制论文”，强调结构创新与解释性，而不是竞品性能。

## 4. 🩷 Fuzzy‑XFD（模糊逻辑 XFD）

**当前支撑：**
- 简化版 FuzzyLogic_simple 在统一基线下已能稳定训练，最新快照约 70.7%（v3 表）——相比最初 20% 有明显提升；  
- 完整的模糊规则/隶属函数/推理框架和部分说明文档。  

**审稿视角下的缺口：**
1. **需要明确对比与定位**  
   - 必须明确回答：  
     - 规则系统 vs NN vs Hybrid（何者在精度 / 解释性 / 不确定性上优势）；  
     - Fuzzy-XFD 的目标是“精度提升”还是“安全兜底”。  
2. **系统对比表仍欠缺**  
   - 建议构建一个三行对比表：Rules-only / NN-only / Fuzzy-XFD：  
     - 准确率、可解释性评分、不确定性/拒判率。  
3. **高风险/工业场景案例**  
   - 至少一个案例展示：当 NN 给出错误且高置信度预测时，Fuzzy 层可以拒绝或给出更安全的判断。  
4. **写作层面**  
   - 强调 Fuzzy-XFD 在“可审计性、安全性、规则迁移”方面的价值，而不是与最强 NN 争 peak accuracy。

## 5. 🟢 Explainable FD Toolkit

**当前支撑：**
- SignalData / ExplainabilityMethod / ModelPlugin 等统一接口已设计并实现；  
- 若干 demo、可视化脚本和工具函数已可用；  
- 与统一 baseline 的接口设计已对齐（但正式 benchmark 仍有限）。  

**审稿视角下的缺口：**
1. **缺乏系统 benchmark**  
   - 需要至少一个 “模型 × 解释方法 × 指标” 的对比表，展示：  
     - 不同方法在覆盖度、稳定性、忠实度上的差异；  
     - 以及计算成本。  
2. **工程应用案例不足**  
   - 1–2 个真实风格案例：给定 unified baseline 的结果，Toolkit 一键生成解释报告，展示工程师如何使用。  
3. **与现有通用库的比较**  
   - 如 Captum / Alibi 等，在 FD 场景下的使用体验与功能覆盖比较。  
4. **写作层面**  
   - 强调“统一性”和“工程落地”，避免沦为纯 API 说明。

## 6. 🟣 LLM‑Enhanced Explainable FD Toolkit

**当前支撑：**
- LLM 接入路径（结构化解释 → 模板 LLM → 对话系统）已有可运行 demo；  
- 多个脚本验证了 pipeline：bridge / test_enhanced_llm / interactive_demo 等。  

**审稿视角下的缺口：**
1. **定量评估 & 用户研究尚缺**  
   - 至少需要一个小规模实验比较：  
     - 传统可视化 vs LLM 文本解释；  
     - 有结构化解释输入 vs 纯 prompt。  
2. **错误与风险分析**  
   - LLM 幻觉、错误诊断建议的案例与防御策略要有专门一节。  
3. **与非 LLM 方法对比价值**  
   - 解释报告生成 vs 交互式对话的优劣对比。  
4. **写作层面**  
   - 明确说明 LLM 的来源、成本与限制（如调用 API 的约束），并强调这是在 Explainable Toolkit 之上的“接口层增强”，不是新的诊断器。

## 7. 🟦 Neural‑Symbolic Theory

**当前支撑：**
- 四层 NeSy 框架（信号层 / 特征层 / 符号层 / 语言层）已在文档中清晰给出；  
- 7 个子项目的大致映射关系已有（谁主要占据哪一层）。  

**审稿视角下的缺口：**
1. **缺少正式的定理/命题与证明思路**  
   - 至少需要 1–2 个有实际意义的理论结果（哪怕在简化假设下），并给出证明 sketch。  
2. **缺少与实验结果的紧密结合**  
   - 推荐选择 1–2 条典型 pipeline（如 TSPN→MoE→Fuzzy 或 Fusion1D2D→Toolkit→LLM），用 NeSy 表示并关联具体实验结果。  
3. **与现有 NeSy 文献的对比辨析**  
   - 阐明本框架在 FD 场景中补齐了哪些空白，而不是泛泛而谈。  
4. **写作层面**  
   - 收紧长篇叙事，增加少量形式化定义、图示和结构化小节，使论文更像理论文章而非长文档。

## 简短建议：优先顺序

- **第一优先**：📘 1D‑2D Fusion  
  - 补多数据集验证 + 消融 + 噪声/工况鲁棒性，即可冲击高水平期刊。  
- **第二优先**：🔴 OperatorAttention + 🟠 MoE  
  - OA：必须拿出一个“性能可对话”的配置；  
  - MoE：补上对比和多 seed/多数据集实验，定位为“可解释专家系统 baseline”。  
- **第三优先**：🟢 Toolkit / 🟣 LLM / 🟩 Fuzzy-XFD / 🟦 NeSy  
  - 每篇各找一个“单点 killer feature”：  
    - Toolkit：统一 benchmark；  
    - LLM：用户研究；  
    - Fuzzy-XFD：安全兜底案例；  
    - NeSy：理论命题 + 一个 pipeline 示例。
